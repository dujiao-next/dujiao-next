# 原生客服首期实施说明

## 已实现

- 用户端跨模板客服挂件：咨询分类、文字消息、历史记录、未读、图片和订单验证关联。
- 后台 `/support` 工作台：会话队列、认领、转派、状态、公开回复、内部备注和快捷回复。
- 用户与访客身份隔离；访客令牌只保存在当前标签页，服务端保存 SHA-256 摘要，7 天过期。
- 前台按站点隔离。后台为平台统一客服团队；普通客服只读取未分配或自己负责的会话，主管可读取全队列。分销商控制台不开放客服管理权限。
- 订单关联复用当前用户 / Guest 订单验证，只返回有限摘要，不包含卡密、订单密码或人工表单内容。当前摘要为关联时快照，不表示后续实时交易状态。
- 图片最多 5 MB，仅 JPEG / PNG / WebP，检查图片结构及像素限制；通过会话授权读取，数据库存储，不使用永久公共上传地址。
- 消息幂等、原子认领、内部备注隔离、管理员变更审计；消息入库与提醒事件同事务。
- WxPusher 标准 UID 定向提醒：加密 App Token、验证码验证 UID 所有权、测试、解绑、延时消费、受理日志、冷却抑制和失败退避。

## 启用步骤

1. 启动更新后的后端，自动迁移客服相关表。更新两个前端。
2. 在权限管理为客服分配 `customer_service`；主管使用 `customer_service_supervisor`。不会自动把旧 `support` 角色扩权为新客服角色。
3. 主管进入“用户管理 → 在线客服 → WxPusher 提醒”，填写 App Token 和公网后台 HTTPS 地址，例如 `https://shop.example/admin`。
4. 客服先在 WxPusher 订阅对应应用，点击“生成参数二维码”扫码订阅，自动获取 UID 后输入收到的验证码确认绑定；也可手动输入 UID 绑定。
5. 如需要，发送测试提醒，再启用应用提醒。密钥只在后台配置页面输入，不要发送到聊天或提交到仓库。

提醒消费者随 API / all 运行模式启动，直接消费数据库持久化事件，不依赖可选 Redis 队列。worker-only 模式不启动本消费者。默认配置关闭，不会因上线代码自动发送真实 WxPusher 消息。

`App.SecretKey` 用于加密通知凭据；变更后需要重新配置 App Token。后台 base URL 应包括真实后台挂载路径；推送链接仍要求后台登录，不能凭 UID 或会话号获得访问权限。

## 当前提醒行为

- 客户消息约 60 秒后仍未读、未公开回复时提醒负责客服；未分配会话提醒已绑定的合格客服。
- 相同客服 3 分钟冷却，冷却内的事件记为抑制；并非完整多会话摘要。
- 每个消费周期只处理一个事件，最多 10 名接收人，减少渠道频率压力；大团队需进一步批处理和全局配额治理。
- 已读、已回复、已解决或超过 24 小时的事件不再提醒。
- 外部受理不等于设备收到或用户阅读。外部发送与本地日志无法原子提交，极端超时仍可能重复；不承诺 exactly-once。

## 当前边界与后续工作

这是可试用的第一版基础闭环，**不是调研文档所有 P0/P1 功能的完整交付**：

- 使用 4–5 秒轮询，不是 WebSocket / SSE；列表最多取当前页 100 个会话，消息按游标分批加载。
- 已支持参数二维码扫码订阅：后台生成 5 分钟一次性二维码，每 11 秒查询扫码 UID，收到验证消息后由当前登录客服确认绑定；无需配置公网订阅回调。保留手动 UID＋验证消息绑定作为备用。
- 尚未实现独立售后工单、营业时间 / 排班配置、首次回复超时主管升级、客户侧 WxPusher 订阅、邮件等提醒兜底。
- 商品 / 订单上下文目前从全站入口手动关联；商品页与订单页专用“一键咨询”入口待补充。
- 未实现 AI、微信内直接回复、自动退款或自动补发卡密。
- 通知投递日志已有持久化表，尚未提供独立日志查询界面；配置 / 绑定审计与保留周期清理需要进一步完善。
- 多实例整体限流、绑定并发 CAS、跨实例共享通知冷却、队列公平性与长期大规模附件存储需进一步压测和治理。
- 访客首次建会话响应完全丢失时仍可能创建重复会话；既有访客令牌 / 登录用户的重复首条提交有创建幂等键。
- 图片不做 EXIF 重编码清理或病毒扫描；上传前需遮挡敏感信息。

## SPT 极简模式

客服提醒面板现在可选择「标准模式」或「SPT 极简模式」。标准模式保留 App Token＋UID 参数二维码订阅。SPT 模式无需创建应用或配置 App Token：

1. 切换到 SPT 极简模式，扫描官方固定二维码获取个人 SPT。
2. 将 `SPT_` 开头的密钥粘贴到密码输入框，点击发送验证消息。
3. 输入 WxPusher 收到的验证码确认绑定。
4. 主管仍需启用全局提醒并保存公网后台 HTTPS 地址；SPT 模式 App Token 可留空。

固定 SPT 二维码不支持本站自动读取扫码结果，必须粘贴获得的 SPT。SPT 是密钥，不能发到聊天、截图或仓库。服务端加密保存，接口和绑定状态不回显；解绑清除密文。切换模式需要重新验证，验证完成后替换旧绑定，取消未完成的标准扫码会话。离线提醒与测试按当前个人绑定模式调用标准或极简 POST 接口，不在 URL 中传递密钥。

已验证无 App Token 的 SPT 绑定、验证确认、脱敏提醒、模式路由和解绑；仅使用模拟接口测试，未输入真实 SPT 或发送真实通知。
